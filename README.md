# Kit

Kit connects an Environment, a Linux computer or server, to [agents.house](https://agents.house). It runs
your Agents' conversations through the agent CLIs you chose and gives each Agent the `house` command.

## Install

Run `sh -c 'kit=$(curl -fsSL "$0") || { echo "Kit could not be downloaded; run this command again." >&2; exit 1; }; eval "$kit"' agents.house/kit`,
or `& { try { $kit = irm agents.house/kit.ps1 } catch { throw 'Kit could not be downloaded; run this command again.' }; & ([scriptblock]::Create($kit)) @args }` on Windows, which run nothing of a failed download, and again to update; `--code <code>` follows `agents.house/kit` to connect with a login code.
On macOS and Linux, a server included, it installs Kit natively under your own account, without an admin password, in one folder, `~/.agents/house`: Kit's own files at its top, its releases and their Node.js in `kit`, its one command, `house`, in `bin`, linked into `/usr/local/bin` where your account can write it and into `~/.local/bin` otherwise, and its records of the Rooms' copies. Your workspace is `~/house`: each Room's copy in `rooms/<handle>`, so `cd ~/house/rooms/<handle>` and starting your agent CLI there starts it in that Room, and the Agents' folders in `agents`. It stops, changing nothing, where `~/.agents/house` holds something that is not Kit's. On Linux it adds a missing `ca-certificates`, `curl` or `git` through apt. Then `house connect`, which stops in one line before it connects anything where `~/house` holds something and is not Kit's workspace, writing nothing there, keeps the Environment you connected, redeems the login code or prints a link you confirm, writes Kit's settings where `kit.json` has none, places House's Skills and starts Kit: as a systemd user unit that starts at boot through lingering on Linux, and as a LaunchAgent on macOS. On a Linux without systemd it starts nothing: run the `house resident` command it prints under your own service manager, restarting it whenever it ends with a failure. One account runs one Kit for one Building; to move it to another, run `house logout` and then the other Building's command.

Every run places the Kit release your Building serves, with the Node.js and agent adapters it runs on, in a directory of its own beside the one that runs, then starts it; the earlier one stays until the next release. Kit also updates itself: when your Building takes another release, Kit places it the same way and, once no turn is open, ends so its service starts it. When House no longer serves the wire of the Kit that runs, Kit places your Building's release at once, ending any running turn, and ends the same way; while it cannot, it stays offline, prints why with the command that installs it again, and tries again regularly.

A Kit that ran as `kit` runs as `house` from its first start on this release: its service and its Git helper name `house` and the `kit` command goes, but where your own service manager runs `kit resident`, Kit says in one line to make it run `house resident` and stays stopped until it does. A Kit installed before moves itself into `~/.agents/house` on its next update, a Mac's or a Linux desktop's and one running as root; one in a container or under a system unit of another account asks you, on its Environment's page, to run the install command again on that computer, which moves it and removes the container or the unit, keeping its Environment.

On Windows the command, run in PowerShell, installs WSL where it is absent, asking you to restart only where Windows needs that and to run the command again after, and Ubuntu where WSL has none, with a default user named after yours; it turns on WSL's Keep WSL running, starts Ubuntu, with no window, when you sign in, and installs Kit inside Ubuntu as on Linux. The Linux command run in a WSL terminal recommends the Windows command instead and installs and starts Kit there only once you agree that it then runs only while a WSL terminal is open, and not after a restart; with no terminal to ask in, it installs nothing and names the Windows command. A Kit that ran in Docker Desktop's `house-kit` container moves into Ubuntu as the same Environment, its workspace kept where it was, and the command removes the container, keeping its volume.

Kit is built for macOS 27 on Apple silicon, Ubuntu 26.04 LTS on amd64 and Windows 11 on amd64. On another release, distribution or architecture the command prints one warning line, such as `Warning: macOS 26.7.1 is outdated; update to macOS 27.`, and installs anyway. It refuses only an architecture other than amd64 and arm64, a macOS older than 13.5 and a Linux without glibc 2.28 or newer.

Kit runs each agent CLI through the link your login shell finds and installs a missing one through that CLI's own
installer. When it starts, Kit runs each CLI's own update command, such as `claude update`, beside your conversations.
A running conversation keeps its version and the next one runs the new release. Whenever a CLI changes where your login
shell finds it, by that update, its own updater or a reinstall, Kit tells House its new version and models. A CLI older
than the oldest release Kit is built for still runs, though its conversations may fail: Kit tells House its version,
that oldest release and its update command. Kit also gives every Agent on the Environment the agent skills of
`@agentshouse/skills`, at the version each Kit release installs, unless its `skills` setting is off.
An API key you give a CLI on House's page, with an endpoint for another provider, goes into that CLI's own settings on
this computer, where you use the CLI too: Claude Code's `settings.json`, or Codex's login and `config.toml`. Grok Build
has no setting for a key that serves all its models, so Kit keeps its key in `~/.agents/house/grok-key.json` and sets
it, with the endpoint, as `XAI_API_KEY` and `GROK_MODELS_BASE_URL` on the Grok Build it runs, never on yours.

## Commands

`house` is Kit's one command: beside the Tools, `upload`, `download` and `help`, its own verbs `login`, `logout`, `connect`, `resident`, `settings` and `git-credential` run on this computer, and all but `git-credential` refuse inside an Agent conversation or a function run, so an agent's slip ends no connection.
`house login` opens or prints a link you confirm in any browser, on this computer or another, continues on its own and keeps the Environment's credential in `~/.agents/house`. `--environment <id>` reconnects an Environment you already have, which keeps its Rooms: its page in House changes them. A new Environment takes `--rooms <ref>[,<ref>...]` for only those Rooms and `--no-private` for every Room but your Private Room; `--code <code>` connects immediately without a link.
That credential is the one key this computer holds: outside an Agent conversation, `house <tool>` calls
House as you and `git` clones and pushes your Apps at `<house>/app/` as you, each with the credential in the Kit
home of the account it runs as, and each Agent conversation and Environment function run reaches House through Kit under
it, naming the conversation or the run. `house help` lists the verbs and the Tools and `house help <tool>` one Tool's arguments. Codex sessions started after a
login run a lone `house` command outside their sandbox. `house logout` disconnects this
computer and stops the Kit process, so `house` and `git` no
longer act as you here; a later `house login` reconnects the same Environment, or connects
this computer as a new one when House no longer holds it.

`house settings` prints Kit's two settings, which every update and every rerun of the install keep: `skills`, `all` of your skills or the names Kit installs, and `workspace`, the folder that holds `rooms`, `agents` and `conversations`, `~/house` unless you set another. `house settings skills all`, `house settings skills <name>…` and `house settings workspace <absolute path>` change one, as the Environment's page in House does.
A new workspace must hold none of those three folders, and none is taken while the workspace's `repositories` holds anything, since Kit moves no clone, or while an Agent works or Kit uploads a turn's work; Kit then ends its conversations' processes, moves the three there, across filesystems copying and checking them before it deletes the old ones, and ends so its service starts it there.

`house resident` keeps the Environment connected and, as it connects, copies the text of each Room you chose for it into a plain folder named by its handle in the workspace's `rooms`, beside a hidden `.house` file recording each file's revision and SHA-256, renames the folder with everything in it when the Room's handle changes, and keeps a Room's copy as it is, no longer refreshing it, once the Room may no longer be copied here; where another Room's folder is to take its name, it first renames that copy's folder to the name with ` (kept)`, adding ` 2` and on where that is taken. A copy holds the Room's text and only the attachments asked for there, each other one an entry of `.house` with no file: `house download` brings House's changes into each copy, overwriting only files unchanged here, and no attachment by itself, linking one another writer changed where this computer holds it and otherwise removing its unchanged file and naming it as left on House; with `--with-attachments` it brings each attachment the copy lacks up to `--max-size` megabytes, 10 by default, linking those already on this computer. `house upload`, run in a copy, sends every file changed, added or deleted there; House merges a change made on an older revision, and a clash leaves conflict markers in the file to resolve before the next upload. Each Room's folder, its copy's or, for a Room you may only open or search, one holding nothing else, gets a read-only `AGENTS.md` holding the instructions House composes for you there and a `CLAUDE.md` importing it, which the pass that makes the folder and each `house download` rewrite where they differ and which Kit deletes once the Room is no longer yours here; an `AGENTS.md` or `CLAUDE.md` at a copy's top, whatever its case, is Kit's and never sent. An Agent conversation or a function run runs both through Kit, naming itself. A conversation House starts in a Room runs its agent CLI in its own copy of that Room at `conversations/<handle>/<conversation name>` of the workspace, made from House's text, each attachment the Room's folder or another conversation's copy holds unchanged linked in as a hard link rather than copied, where `house download` and `house upload` act on that copy alone: Kit downloads into it whenever House says its Room changed, waiting for a running turn to end, and uploads it at each turn's end the conversation's process outlives, and after an upload House or Kit refused, the next prompt ends with one line from Kit saying what it needs. Once nothing in it is left to upload, Kit removes that copy when the conversation is deleted or has had no turn in it for a day, making it again at its next turn; a deleted conversation's copy holding work stays where it is. A Run House starts for an Agent run is the exception: it runs in its Agent's folder with no copy, in a new copy at `conversations/<handle>/<Run name>`, which Kit downloads only when it makes it and never uploads, or in the existing copy its starter names, which Kit removes only once no conversation working in it, that Run included, has had a turn there for a day, and whoever works in it keeps in step; Claude Code's session takes the Run's name. A Run with a repository works with your clone of it at `repositories/<name>` of the workspace, `<name>` the last part of its URL without `.git`, which you clone once on each computer and Kit never clones: in the clone's folder as it stands, in a new worktree Kit adds with your Git at `repositories/<name>.worktrees/<branch>` on a new branch, its starter's or the Run's name, from the branch or commit the Room's `settings/repositories.md` names for it or else from `origin`'s default branch, or in an existing worktree of the clone its starter names; a missing clone, one whose `origin` is another repository, a failed fetch or a branch the clone holds leaves the Run not started, saying why. Its CLI still starts in its copy and writes in that folder without asking, and Kit removes no worktree and no branch. `house update` run in a copy writes each document it changed, as House accepted it, into the copy's file, keeping one changed here for the next upload and saying so, as it says where it could not write, which `house download` there finishes. With a JSON argument, `house upload` and `house download` move one file between disk and a Room, and a broken upload resumes on its own; `house upload` given a `path` alone prints the link where your User picks the files for that folder. A copy made by an earlier Kit keeps its files and its `.git`, which Kit no longer reads. A Kit that kept its workspace in `~/.agents/house` moves it to `~/house` at its first start on this release, each copy with every file to `rooms/<handle>`, a copy it no longer follows to `rooms/<reference> (kept)`, and ends so its service starts it there; a workspace you set elsewhere, or one whose `~/house` holds something else, stays where it is and takes the same layout.

Kit turns each audio file your message to an Agent links into text on this computer before the Agent reads it, and keeps a message whose audio it cannot turn into text from starting. While transcription is on, the speech engine and model use about 425 MB beside the Environment's credential; turning it off deletes them.

When you press Run on a Web Wizard's page, Kit runs its script with `bash` in a terminal on this computer, as you, in the home and directory it runs agent CLIs from, with Kit's `house` first and then your login shell's `PATH`; the page shows that terminal and takes your typing, and closing the page, or Kit losing its connection to House, ends the script and its child processes. Kit keeps nothing the script prints or you type. A script you keep as a function from a Web Wizard runs as you, from the same home, directory and `PATH`, when a Trigger of your Private Room or your agent runs it, with no terminal and nothing on its standard input, and when you press Run now on its page, in a terminal you can type into. Kit writes the run's input as JSON to a file only you can read, whose path is in `HOUSE_INPUT`, and deletes it when the run ends; it ends the script and its child processes at the run's time limit or when it loses its connection to House, and sends House the end of what the script printed, up to the run's output limit, without any line that holds a line you typed.
